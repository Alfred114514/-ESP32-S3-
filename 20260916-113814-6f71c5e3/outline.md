## 4. 系统稳定性攻坚

### 4.1 PSRAM 任务栈与 NVS/Flash 擦写的断言崩溃

**论点**：识别任务在 PSRAM 栈上调用 NVS 读会踩中 cache 禁用窗口导致崩溃，工程上用"特征库常驻 PSRAM 缓存、识别路径零 NVS"彻底消除该冲突。

**写作指导**：先讲 flash 擦写期间 cache 被禁用、CPU 只能执行访问内部 RAM 这一底层约束，再讲断言崩溃的具体表现，最后讲 cache_reload 读写分离设计与内部 RAM 栈调用的顺序约束。

### 4.2 看门狗复位与调度饿死

**论点**：100Hz tick 下 pdMS_TO_TICKS 整数截断为 0 会使忙等循环饿死空闲任务并触发任务看门狗复位，是两个直接引发线上复位复现问题的根因。

**写作指导**：讲清 TICK 截断机制、IDLE 任务与 TWDT 的依赖关系、以及为何修复方式是 vTaskDelay(1) 而非提高优先级或加大超时。

### 4.3 死锁、唤醒失效与屏幕显示异常

**论点**：非递归 LVGL 锁的自嵌套、深睡唤醒源受 RTC GPIO 编号约束、RGB565 字节序与面板大端配置不匹配，是三类彼此独立的稳定性缺陷。

**写作指导**：三类问题分述，每类给触发路径、根因、修复方式与替代方案。

### 4.4 无线共存与服务阻塞

**论点**：单射频芯片的 AP 与 STA 信道共存冲突、以及 esp_http_server 单任务模型被长连接流式响应阻塞，都必须在架构层而非参数层解决。

**写作指导**：先讲 ASSOC_TOOMANY 反复断连的根因与纯 STA 取舍，再讲 /stream 无限循环冻结整个 HTTP 服务器导致控制指令饿死，UDP 独立任务的解耦方案。
